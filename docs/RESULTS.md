## 3. 실험별 결과

### 3.1 채널·속도·가시선 (N1, N3, P1)

`results/summary/harq.md`에 조건 39개 전부가 있다. 대표 조건:

| 조건 | 블록 | 첫 실패 L1 / 작은 NRx | 복구 | 재전송/100 L1 → 우리 (비율) | 4회 뒤 실패 |
|---|---|---|---|---|---|
| UMi 3 km/h | 20,480 | 10.3 / 9.8% | 22.8% [21.2–24.4] | 17.5 → 13.2 (0.751) | 2.21 → 1.48% |
| UMi 30·60·120 km/h | 20,480·20,480·10,240 | 10.3% | 21.8–22.3% | 0.75–0.76 | 2.1–2.2 → 1.5% |
| UMi 가시선 / 비가시선 | 10,240 | 16.2 / 4.4% | 18.7 / 35.9% | 0.75 / 0.62 | 4.05 → 2.67 / 0.29 → 0.11% |
| UMa 3 km/h (두 시드 묶음) | 10,240 + 10,240 | 13.1–13.6 / 7.5–7.8% | 56.5 / 57.5% | 0.437 / 0.425 | 2.2 → 0.8–1.0% |
| UMa 30·120 km/h | 10,240씩(+30 km/h 추가) | 13.1–13.6% | 55.8–57.7% | 0.42–0.45 | 2.1 → 0.9% |
| UMa 가시선 | 20,480 | 17.8–18.0% | 27–28% | 0.69–0.70 | 4.2–4.4 → 2.6–2.8% |
| UMa 비가시선 | 20,480 | 11.4–11.6% | 72–73% | 0.26–0.27 | 1.0–1.1 → 0.2–0.3% |

분석.
- 속도가 결과를 바꾸지 않는다. 재전송 사이 채널 변화는 3 km/h 0.5–4.8%에서 60 km/h 42–50%로 커지지만, 273 PRB 전대역이라 빠른 페이딩은
  주파수로 평균되고, 블록 성패를 정하는 사용자 이득(22 ms에 0.26 dB 변화)과 짝 상관(0.027 변화)은 그대로다. 같은 짝으로 다시 보내면 같은
  조건을 다시 받는다.
- UMa에서 효과가 큰 이유: 지연 확산이 커서 cuPHY 기존 수신기의 채널 추정이 약하다(첫 실패 13.6%, 작은 NRx만 써도 7.8%). Large NRx는
  UMi로 학습됐는데도 UMa 실패의 57%를 살린다.
- 가시선에서 효과가 작은 이유: 가시선 쌍은 신호가 강하게 겹치는 경우가 많아(상관 ≥ 0.6이 26–27%) 어떤 수신기로도 못 푸는 실패가 많다.

### 3.4 다른 복구 방법 (N5, N12)

같은 슬롯·같은 실패 블록(NVlabs LS 기존 수신기 기준; cuPHY보다 약해 절대 비율은 3.1과 다르다).

| LDPC 50회 | 7.0% | 9.9% |
| 반복 검출–복호(IDD, SIC) | 19.4% | 20.6% |

- 연쇄(작은 NRx 먼저, 실패하면 Large NRx): 살리는 양은 같고 Large NRx 실행이 30%(UMi), 39%(UMa) 준다.

### 3.5 지연 (N7)

DDDSU, grant 선행 4 ms, Large NRx 결과는 L1 1.4 + 6.3 = 7.7 ms.

| 방식 | 복구 안 된 실패 p50/p99 | 복구된 블록 p50 | 재전송/100 (UMi / UMa) |
|---|---|---|---|
| HARQ만 | 9.4 / 24.4 ms | 9.4 ms | 17.5 / 20.4 |
| 병렬 | 9.4 / 24.4 ms | 7.7 ms | 15.5 / 16.2 |
| 실패 조각 ≤ 5면 기다림 | 9.4 / 24.4 ms | 7.7 ms | 14.5 / 14.6 |
| 복구를 기다림 | 14.4 / 29.4 ms | 7.7 ms | 13.2 / 8.7 |
| 완벽한 예측(상한) | 9.4 / 24.4 ms | 7.7 ms | 13.2 / 8.7 |

- 병렬 복구는 HARQ만 쓰는 것보다 지는 지표가 없다.
- 실패 조각 수가 복구를 예측한다(UMi: 1조각 98%, 2–5조각 84–93%, 10조각 전부 10%). UMa에서는 10조각 전부 실패해도 49%(비가시선 66%)가
  살아나 조각 수만으로는 부족하다 → N10 예측기.

### 3.6 링크 적응 (N6)

복구를 성공으로 치면 외부 루프가 MCS를 1–1.5단계 올린다. 처리량 배수(우리 / 작은 NRx, 기준은 기존 수신기):

| 조건 | 목표 10% | 목표 3% |
|---|---|---|
| UMi | 1.02–1.21 / 1.00–1.04 | 1.02–1.18 / 0.98–1.04 |
| UMa | 1.22–1.42 / 1.07–1.33 | 1.08–1.75 / 1.03–1.57 |
| UMa 비가시선 | 1.19–1.40 / 1.12–1.30 | 1.08–1.81 / 1.06–1.69 |
| UMa 가시선 | 1.09–1.32 / 1.01–1.15 | 1.05–1.22 / 1.01–1.07 |

UMa에서는 작은 NRx도 처리량을 크게 올리므로, 우리 방식의 추가 이득은 작은 NRx 대비 2–20%p다. MCS 사다리가 16QAM(MCS 10–16)뿐이라
높은 SNR에서는 MCS 16에 막힌다.

### 3.7 짝 고르기 (P2)

사용자 U명을 떨어뜨리고 사용자 0의 짝을 고른다(무작위 / (1−ρ²)·min(이득) 최대 / 상관 최소).

| 조건 | 짝 상관 | 재전송/100 L1 → 우리 | 4회 뒤 실패 |
|---|---|---|---|
| UMi 무작위 | 0.46 | 16.1 → 12.2 | 1.92 → 1.30% |
| UMi 4·8·16명 중 고른 짝 | 0.40·0.35·0.30 | 14.0·12.8·14.4 → 11.0·10.5·12.3 | 1.6–2.0 → 1.2–1.6% |
| UMi 8·16명 중 상관 최소 | 0.27·0.22 | 17.3·19.8 → 14.7·17.3 | 2.2·2.6 → 1.7·2.2% |
| UMa 무작위 | 0.47 | 21.0 → 9.1 | 2.02 → 0.88% |
| UMa 4·8·16명 중 고른 짝 | - | 17.7·16.4·15.7 → 7.7·7.8·8.2 | 1.7–1.9 → 0.87–0.91% |
| UMa 8명 중 상관 최소 | - | 20.3 → 11.1 | 2.23 → 1.31% |

- 무작위 짝 + 복구가 고른 짝 + 기존 수신기와 같거나 낫다(UMa에서는 훨씬 낫다).
- 상관만 보고 고르면 무작위보다 나쁘다: 상관이 낮은 짝은 신호가 약한 경우가 많다. 짝은 이득과 상관을 함께 봐야 한다.

|---|---|---|---|---|

| 3명 (미세 조정 NRx) | 13.8% | 54.8% | 48.2% | 69.7% |

- 사용자가 늘수록 실패가 급격히 늘어 복구가 필요한 상황이 많아진다. 안테나가 많아도 수신기로 고칠 실패(상한)는 절반 이상이다.
- 약점: 짧게 추가 학습한 모델(3–4명, 8 RX)은 K-best보다 약하다(8 RX UMa 제외). 넓힌 8 RX 모델은 학습 전에는 기존 수신기보다 나빴고
  (살린 실패 8.1%), 학습 28만 → 49만 반복에 38.0 → 38.8%로 거의 멈췄다. NVlabs 원 모델은 1천만 반복 학습이다. 따라서 "Large NRx가 필요하다"는
  2명·4 RX(원 모델)에서만 주장하고, 3–4명·8 RX에서는 "복구 경로는 가장 강한 수신기를 쓰면 된다"로 쓴다. 추가 학습(학습률 3e-4 → 5e-5)을
  진행 중이다(2026-10-18).

### 3.9 GPU 수요 (N9)

| 조건 | 복구가 필요한 슬롯 | 기지국 4개가 쓰는 GPU 한 장의 몫(동시 실행 4개 기준) |
|---|---|---|
| UMi Eb/No 8 dB | 23% | 58% |
| UMa 전체 | 24% | 60% |

N13 실측(A100, TensorRT FP16, 엔진만): Large NRx는 한 번에 GPU 한 장을 다 쓴다. 동시 실행 1/2/4/8개에서 처리량 233/207/194/193회/초, 1회 지연 4.3/9.6/20.5/41.3 ms. 작은 NRx는 740/689/632/623회/초(1.3 ms). 위 표의 "동시 실행 4개" 가정은 틀렸다: 기지국 하나가 초당 92–96회(상향 슬롯 400개/초 × 23–24%)의 복구를 요구하므로, 모든 실패를 Large NRx로 복구하면 A100 한 장이 기지국 약 2.4개를 감당한다. GPU가 귀하므로 살릴 블록을 고르는 것(N10)과 연쇄(N12, Large NRx 실행 30–39% 감소)가 필요하다. 지연 계산(N7)은 채널 추정·복호를 포함한 6.3 ms를 보수적으로 그대로 쓴다.

## 4. 남은 일과 진행 중인 실험 (2026-10-18)

- N10/N11: L1 결과만으로 복구 성공을 예측하는 모델과 GPU 예산 대비 복구 가치 곡선.
- N13: Large NRx 동시 실행 수별 처리량·지연 실측.
- N14: 3–4명 모델·8 RX 모델 추가 학습과 재평가.
- N5 UMa 추가 시드(실패 233 → 약 900개), 소형 기지국 가시선/비가시선·대형 120 km/h 추가 시드.
